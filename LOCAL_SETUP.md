# CLIProxyAPI Local Setup

Deployment directory: `/opt/cliproxyapi`

## Access

- Public HTTPS base URL: `https://tradetd.cloud-ip.cc/v1`
- Local API base URL: `http://127.0.0.1:8317`
- Public port: `443/tcp`
- Front-end home page: `https://tradetd.cloud-ip.cc/`
- Existing backend API: `https://tradetd.cloud-ip.cc/api/`
- Client API key: `sk-cli-your-client-key`
- Management key: `mgmt-change-me`

Notes:

- `8317` is now bound to `127.0.0.1` only. External clients must use the HTTPS endpoint above.
- UFW currently allows `80/tcp` and `443/tcp`.
- The front-end and `/api/` remain active; `/v1/` is reverse-proxied to CLIProxyAPI.

## Quick checks

List models:

```bash
curl https://tradetd.cloud-ip.cc/v1/models \
  -H 'Authorization: Bearer sk-cli-your-client-key'
```

Chat completion:

```bash
curl https://tradetd.cloud-ip.cc/v1/chat/completions \
  -H 'Authorization: Bearer sk-cli-your-client-key' \
  -H 'Content-Type: application/json' \
```

## Teammate keys

List all current client keys:

```bash
cliproxy-list-user-keys
cliproxy-list-user-keys --full
```

Generate a dedicated key for a teammate:

```bash
cliproxy-add-user-key alice --show-full
```

Rotate a teammate key:

```bash
cliproxy-add-user-key alice --replace --show-full
```

Revoke a teammate key:

```bash
cliproxy-revoke-user-key alice
```

Show usage grouped by client API key:

```bash
cliproxy-show-usage
cliproxy-show-usage alice --details
cliproxy-show-usage --json
```

Usage notes:

- Usage is tracked per client API key, so each teammate should use a separate key.
- The statistics are proxy-observed request/token totals, not the upstream provider's remaining balance or quota.
- The current implementation keeps usage stats in memory, so they can reset after a proxy restart unless exported/imported separately.

## Upstream accounts

Current codex/OpenAI-style upstream routing strategy:

```bash
cliproxy-routing
```

Set upstream routing strategy:

```bash
cliproxy-routing round-robin
cliproxy-routing fill-first
```

Notes:

- `round-robin`: spread requests across available upstream accounts.
- `fill-first`: use the first available account until it hits a limit, then move on to the next one. This is often better for subscription-style rolling caps.
- This deployment keeps the global strategy on `fill-first`, but overrides `antigravity` to `round-robin` via `routing.provider-strategy.antigravity=round-robin`.
- Automatic switching is driven by actual upstream quota/limit responses, especially HTTP `429` / `usage_limit_reached`.
- The proxy does not currently preemptively switch based on a custom “used X tokens, then rotate” threshold.
- Higher `priority` wins before routing strategy is applied. This deployment currently prefers OAuth (`100`) over API-key upstreams (`-100`), so normal unprefixed Codex traffic goes to OAuth first and only falls back to API-key upstreams when OAuth accounts are unavailable/cooling.

List configured codex upstream API-key accounts:

```bash
cliproxy-list-codex-upstreams
cliproxy-list-codex-upstreams --full
```

Add a codex upstream API-key account using the same model mappings as the current upstream:

```bash
cliproxy-add-codex-upstream sk-xxxxx --prefix oa2 --show-full
```

Remove a codex upstream API-key account:

```bash
cliproxy-remove-codex-upstream oa2
cliproxy-remove-codex-upstream 1
```

Show current runtime upstream account state:

```bash
cliproxy-upstream-status
cliproxy-upstream-status --details
cliproxy-upstream-status codex --json
```

The local command above reads the localhost-only Management API endpoint `GET /v0/management/runtime-auths?provider=codex`.

Antigravity local operations:

```bash
./scripts/cliproxy-antigravity-login
cliproxy-antigravity-status
cliproxy-antigravity-status --details
cliproxy-antigravity-enable ag2
cliproxy-antigravity-disable ag2
cliproxy-antigravity-test ag2 --model gemini-3-flash
cliproxy-antigravity-quota
cliproxy-antigravity-quota --model gemini-3-flash
cliproxy-antigravity-quota --prefix ag2 --details
```

Antigravity command notes:

- `./scripts/cliproxy-antigravity-login` runs the in-container Antigravity OAuth login flow with `-no-browser`.
- `cliproxy-antigravity-status` lists prefix, email, runtime state, recent error type, and model count.
- `cliproxy-antigravity-enable` / `cliproxy-antigravity-disable` toggle one Antigravity auth by prefix, email, or auth id.
- `cliproxy-antigravity-test` sends one targeted request through a specific Antigravity prefix.
- `cliproxy-antigravity-quota` queries Antigravity live and shows per-model remaining quota percentages.
- `cliproxy-antigravity-quota --model ...` is the fastest way to compare one model across all Antigravity accounts.

Show the latest seen upstream OAuth quota per account:

```bash
cliproxy-oauth-quota
cliproxy-oauth-quota --details
cliproxy-oauth-quota --probe
cliproxy-oauth-quota --json
```

Quota notes:

- `cliproxy-oauth-quota` reads recent request logs under `/opt/cliproxyapi/logs` and extracts the latest seen `X-Codex-*` quota headers per OAuth account.
- `P-LEFT` / `S-LEFT` are computed as `100 - used_percent`.
- If an account has not served a recent request yet, its quota fields remain `unknown` / `-` until the next successful upstream response is logged.
- `cliproxy-oauth-quota --probe` sends one small live request to each OAuth account and refreshes the displayed quota from the upstream response headers directly.

Remote HTTPS API for authenticated clients:

```bash
curl 'https://tradetd.cloud-ip.cc/v1/api/oauth-quota?probe=1' \
  -H 'Authorization: Bearer sk-team-alice-xxxxxxxxxxxxxxxx'
```

Remote HTTPS API for live Antigravity quota:

```bash
curl 'https://tradetd.cloud-ip.cc/v1/api/antigravity-quota' \
  -H 'Authorization: Bearer sk-team-alice-xxxxxxxxxxxxxxxx'

curl 'https://tradetd.cloud-ip.cc/v1/api/antigravity-quota?model=gemini-3-flash' \
  -H 'Authorization: Bearer sk-team-alice-xxxxxxxxxxxxxxxx'

curl 'https://tradetd.cloud-ip.cc/v1/api/antigravity-quota?prefix=ag2&details=1' \
  -H 'Authorization: Bearer sk-team-alice-xxxxxxxxxxxxxxxx'
```

Antigravity quota notes:

- This endpoint queries Antigravity live and returns per-model remaining percentage from `quotaInfo.remainingFraction`.
- `model=...` highlights one specific model in each account as `matched_model`.
- `details=1` returns the full per-model quota list for each account.

State meanings:

- `online`: currently available for routing
- `cooling`: quota/rate-limit cooldown is active and the auth is waiting to recover
- `retry-wait`: temporarily unavailable and waiting for the next retry time
- `disabled`: manually disabled

Manual pinning:

- If an upstream has a `prefix`, you can force that upstream with a prefixed model name such as `oa2/gpt-5.4-mini`.
- Without a prefix, matching upstreams participate in the global routing strategy automatically.

Important distinction:

- `codex-api-key` entries are for upstream API-key style accounts.
- Real `GPT Plus / ChatGPT subscription` accounts should be added through Codex OAuth login, not by putting the email/password or subscription account into `codex-api-key`.
- Once multiple Codex OAuth accounts exist, they also participate in the same provider-level routing and automatic failover.

## How teammates use it

Give each teammate:

- Base URL: `https://tradetd.cloud-ip.cc/v1`
- Their own generated API key
- A model name from the configured list, for example `gpt-5.4-mini`

OpenAI-compatible example:

```bash
curl https://tradetd.cloud-ip.cc/v1/chat/completions \
  -H 'Authorization: Bearer sk-team-alice-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-5.4-mini","messages":[{"role":"user","content":"Say hello."}],"stream":false}'
```

## Operations

Start or update:

```bash
cd /opt/cliproxyapi
docker compose up -d
```

Stop:

```bash
cd /opt/cliproxyapi
docker compose down
```

Logs:

```bash
cd /opt/cliproxyapi
docker compose logs -f cli-proxy-api
```

Status:

```bash
cd /opt/cliproxyapi
docker compose ps
```
